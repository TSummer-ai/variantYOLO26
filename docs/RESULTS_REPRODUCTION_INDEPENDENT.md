## 0. 一句话结论

**本仓库文档中的全部数值型结论都可以在完全不同的软硬件环境下复现**，包括最后一行
MV-Fuse 的 **0.2788 / 0.4754**：全栈表、内部口径表、MV-Fuse 的 6 个变体（全量 + 留出半集）
共 20 余个数字，逐个对到小数点后 3~4 位。此外本次复现额外发现两个工程要点（见 §7、§8）。

## 6. 新增实验：延迟 NMS 融合（本报告独立提出，非作者方法）

**动机**：尺寸门控融合在**每个视角内部**各做一次 NMS（iou=0.7），会把跨视角本可互相补全的
候选提前删掉。把视角内的 NMS 推迟到融合之后只做一次（全局 NMS 0.6），候选池更大。

**措辞提醒**：本项目 checkpoint 的 `head.end2end == False`（`_end2end` 标记缺失，见 README
「重大更正」），因此 `predict(nms=False)` **不是 NMS-free(o2o) 头**，而是"o2m 头 + 关闭 NMS"。
本实验用的正是这个语义，属于**后处理策略**的改变，不涉及头本身。

| 方案（每图均为 4 次前向，成本相同） | 全量 548 | 留出 274 |
|---|---|---|
| A 尺寸门控融合（视角内 NMS） | 0.2749 / 0.4683 | 0.2751 / 0.4726 |
| B A + 一致性重打分（= MV-Fuse） | 0.2788 / 0.4754 | 0.2790 / 0.4802 |
| C 尺寸门控融合（延迟 NMS） | **0.2790 / 0.4776** | **0.2793 / 0.4801** |
| **D C + 一致性重打分** | **0.2816 / 0.4824** | **0.2817 / 0.4843** |

- **C vs A：+0.0041 AP50-95 / +0.0093 AP50**（留出 +0.0042），**零额外前向**；
- **D vs B（MV-Fuse）：+0.0028 AP50-95**（留出 +0.0027）；
- 两个划分上方向一致，说明不是划分偶然。

脚本：[`probe_deferred_nms_fusion.py`](../scripts/probe_deferred_nms_fusion.py)。

## 7. 复现中发现的坑：`nms` 状态会在进程内残留

同一进程里**调用过一次 `predict(nms=False)` 之后，再调用不带 `nms` 参数的 `predict` 会继承
"关闭 NMS"的状态**。同图同参数实测（`imgsz=960, conf=0.001, iou=0.7, max_det=3000`）：

| 调用顺序 | 返回框数 |
|---|---|
| 1) `predict(...)`（默认） | 1665 |
| 2) `predict(..., nms=False)` | 3000 |
| 3) `predict(...)`（默认，再一次） | **3000 ← 被污染** |
| 4) `predict(..., nms=True)`（显式） | 1665 |

**影响**：任何在同一个进程里交替使用 `nms=False` 与默认 `predict` 的评测都会失真——
"视角内 NMS"的对照组会被悄悄替换成"延迟 NMS"，从而**把增益算成 0**（复现中实测到过：
同一算法在混合进程里得到 0.2790，在干净进程里是 0.2749）。

**规避**：两条路径都必须**显式**传 `nms=True` / `nms=False`，或者干脆分进程跑。
本仓库新增的脚本已按此处理。

## 8. 诚实边界

- 本报告只复现**推理期/评测期**的结论；训练未复现（作者记录 2~9 小时/模型），直接使用仓库自带权重。
- C/D 两组的参数（`W`、`big_px=48`、`merge_iou=0.6`）沿用作者的设定，**没有为本方法单独调参**，
  也没有单独的调参划分；全部数字为**单次评测**，+0.0028 量级需要多种子复核后再作为结论引用。
- 延迟 / FPS / GFLOPs 与显存的结论未复核（CPU 环境）。GFLOPs 已核对一致：
  base-640 5.9 / p2-640 7.7 / p2-960 17.6。
- 本报告的 A/B 两组即作者文档中的"尺寸门控融合 / MV-Fuse"；C/D 为本报告新增，尚未经过作者复核。
