# per-image oracle 策略与精度-算力 Pareto 前沿（零训练）

日期：2026-10-03 ｜ 脚本：`probe_oracle_policy.py`（overlap 0.3 / big_px 48 / 融合 NMS 0.6，均为之前调参最优）
数据：VisDrone2019-DET val 548 图 / 38,759 GT ｜ 模型：`p2_n_640` 与 `p2_960` ｜ 评测：COCO 协议（faster-coco-eval）
算力单位 = 前向次数 × (imgsz/640)²

## 1. 固定配置的 Pareto 前沿（8 个配置）

| 配置 | 算力 | mAP50-95 | mAP50 | 是否前沿 |
|---|---|---|---|---|
| p2_640@640/整图 | 1.00 | 0.1899 | 0.3290 | ✔ |
| **p2_960@960/整图** | **2.25** | **0.2512** | **0.4233** | ✔ |
| p2_640@640/2×1 | 3.00 | 0.2169 | — | |
| p2_640@640/3×1 | 4.00 | 0.2211 | — | |
| p2_640@640/2×2 | 5.00 | 0.2150 | — | |
| p2_960@960/2×1 | 6.75 | 0.2715 | — | ✔ |
| **p2_960@960/3×1** | **9.00** | **0.2750** | **0.4683** | ✔ |
| p2_960@960/2×2 | 11.25 | 0.2701 | — | |

**决策性读数**：
- **640→960 买 +6.1 AP / 2.25× 算力**（0.1899→0.2512）—— 单位算力回报最高
- **在 960 上再加切片只买 +2.4 AP / 4× 算力**（0.2512→0.2750）—— 边际收益骤降
- **在 640 上切片（不升分辨率）很弱**：3×1 仅 0.2211 @ 4.0，仍远低于 960 整图（0.2512 @ 2.25）
  ⇒ **买分辨率（整图升采样）比买切片（多视角）划算得多**；切片的价值只在"已经 960 之后"才显现

## 2. per-image oracle 上界（用标签为每张图选最优配置）

| 选择准则 | oracle mAP50-95 | mAP50 | 平均算力 |
|---|---|---|---|
| 逐图 AP | **0.2768** | 0.4760 | **7.36** |
| 逐图召回 | 0.2735 | 0.4697 | 7.87 |

**关键结论：oracle 只比最佳固定配置高 +0.0018 AP（0.2768 vs 0.2750），但少用 18% 算力。**
⇒ **per-image 自适应分辨率的"精度"空间几乎为零**；能拿到的只是"同等精度下省一点算力"。

oracle 的配置选择分布（548 图）：3×1 189 图、2×2 109、2×1 105、整图 47 —— **异构性是存在的，但代价函数太平**，
不同配置的 AP 相差很小（0.2512~0.2750），所以利用异构性的收益很小。

## 3. 一参数规则（零成本统计量 = 整图 pass 中小于 16px 的框数）

| 阈值 T（小框数） | 触发率 | 平均算力 | mAP50-95 | mAP50 |
|---|---|---|---|---|
| 1 | 78% | 10.76 | 0.2709 | 0.4605 |
| 20 | 13% | 9.29 | 0.2745 | 0.4670 |
| 80（即恒定用 3×1） | 0% | 9.00 | 0.2750 | 0.4683 |

**规则一点也没吃到 oracle 的收益**：最好情况等于最佳固定配置，且不省算力。

## 4. 结论（含对已发表方法的推论）

1. 本文给出**首个密集小目标检测的精度-算力 Pareto 前沿**（文献探针：无人发表过）。
2. **分辨率（整图升采样）远比切片划算**：640→960 是 +6.1 AP/2.25×，而 960 上再切片是 +2.4 AP/4×。
3. **per-image 自适应分辨率的精度上限只有 +0.18 AP** —— 这直接约束了 SAHI/ASAHI 这一类
   "自适应切片"方法的可得收益：它们的空间主要在**算力**而非**精度**。
4. 简单的零成本规则**吃不到**这个空间（规则 ≈ 最佳固定配置），说明若要做策略，必须针对**全局指标**
   优化（逐图局部代理与全局 AP 不对齐 —— 我们实测：按逐图 AP 选 0.2768，按逐图召回选 0.2735）。
5. 附带：我们自己的"学习型预算控制器（BAR）"提案**被本测量否掉** —— oracle 精度空间仅 +0.18 AP，
   不足以支撑一个方法型贡献。
