## 5. 结论

1. **训练配方完整可复现**：逐轮曲线、最终内部指标（0.2692 vs 0.269）、COCO 协议（0.2497 vs 0.2474）、
   切片融合（0.2764 vs 0.2750）、MV-Fuse（0.2809 vs 0.2788）**全部对上**，
   且系统性略高约 **+0.002**（应源于 ultralytics / 依赖版本差异，本机为 8.4.173）。
2. **独立训练出的模型全栈 0.2809，略优于仓库发布的 0.2788**。
3. 训练期间发生 **4 次中断**（系统内存耗尽 ×2、PyTorch 分配器内部断言 ×1、手动降 worker ×1），
   均由"看门狗 + 从 `last.pt` 续训"恢复，**未影响最终结果**。

## 6. 复现命令（本机实际使用）

```bash
# 环境：CUDA 版 torch（独立目录）+ ultralytics
pip install --target <dir> torch==2.14.1+cu130 torchvision==0.29.1+cu130 \
    --index-url https://download.pytorch.org/whl/cu130

# 数据 yaml 指向本地 VisDrone（YOLO 格式）
#   path: <DATA_ROOT>
#   train: VisDrone2019-DET-train/images
#   val:   VisDrone2019-DET-val/images

# 训练（等价于 scripts/run_p2_960.sh，用 Python API 以便控制）
python train_runner.py \
    --cfg  <yolo26-p2.yaml> \          # 与 weights/p2-960 内嵌架构逐位一致（已核对）
    --pretrained yolo26n.pt \          # COCO 预训练，部分加载
    --data <visdrone.yaml> \
    --epochs 100 --imgsz 960 --batch 4 --workers 2 --seed 0 --device 0

# 评测
yolo val model=<best.pt> data=<visdrone.yaml> imgsz=960 max_det=1000   # -> 0.2692
python scripts/oracle_decompose.py --weights <best.pt> --imgsz 960 --head o2m   # COCO 协议
python scripts/probe_mvfuse.py    --weights <best.pt> --imgsz 960 --tag retrained
```

## 7. 诚实边界

- **单种子**（seed=0），未做多种子；±0.002~0.003 的差异本身就在单种子噪声附近，故上述
  "略优于"应理解为"等价"，不宜作为"改进"主张。
- `best.pt` 按本仓库定义取**训练期 val（max_det=300）最优轮次**（本次为 ep87）；
  而 `max_det=1000` 的 0.269 是事后重评口径，两者不可混用。
- 训练期因**系统物理内存不足（15.6 GB）**发生中断；生产环境建议内存 ≥32 GB，
  或保持 `workers ≤ 2`。
- 延迟 / 显存 / 训练耗时的横向对比未做（本机为 Windows + 自装 CUDA 版 torch，与作者 Linux 环境不可直接比）。
